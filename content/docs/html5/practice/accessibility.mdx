Accessibility (a11y) ဆိုတာ webpage ကို မသန်စွမ်းသူတွေ အပါအဝင် လူတိုင်း အသုံးပြုနိုင်အောင် ပြုလုပ်ခြင်း ဖြစ်ပါတယ်။ Screen reader သုံးတဲ့ မျက်မမြင်သူတွေ၊ keyboard တစ်ခုတည်းနဲ့ သုံးတဲ့သူတွေအတွက်ပါ အဆင်ပြေစေပြီး search engine ကလည်း ပိုကောင်းကောင်း နားလည်နိုင်ပါတယ်။ ဒါကြောင့် accessibility နဲ့ SEO (Search Engine Optimization) က များစွာ ဆက်စပ်မှု ရှိပါတယ်။

### Accessible လုပ်ရတဲ့ အကြောင်းရင်း

Web ဆိုတာ လူတိုင်းအတွက် ဖွင့်ထားတဲ့ နေရာ ဖြစ်သင့်ပါတယ်။ တစ်ချို့သူတွေက ပုံမမြင်နိုင်ဘဲ screen reader သုံးရပြီး တစ်ချို့က mouse မသုံးနိုင်ဘဲ keyboard နဲ့သာ သွားလာပါတယ်။ ကိုယ့် page ကို accessible ဖြစ်အောင် လုပ်ထားရင် ဒီသူတွေ အားလုံး အလွယ်တကူ သုံးနိုင်ပြီး အခက်အခဲလည်း နည်းပါတယ်။

**ဥပမာ -**

```html
<p>ပုံကို ကြည့်နိုင်ရင် ပုံထဲက <strong>သစ်သီးပန်းကန်</strong> ကို မြင်ရပါတယ်။</p>
```

မှတ်ချက် — ပုံထဲက အချက်အလက်ကို စာသားအနေနဲ့ပါ ထည့်ပေးတာက ပုံမမြင်နိုင်သူတွေအတွက် အချက်အလက် ဆုံးရှုံးမှု မဖြစ်စေပါဘူး။

### Semantic HTML နှင့် Screen Reader

Semantic tag တွေက ထို tag ရဲ့ အဓိပ္ပာယ်ကို screen reader သိစေပါတယ်။ ဥပမာ — `nav` ထဲက link တွေက navigation ဖြစ်ကြောင်း၊ `main` က အဓိက အကြောင်းအရာ ဖြစ်ကြောင်း screen reader ဖတ်ပေးပါတယ်။ ပုံသွင်ပြင်အတွက်သာ သုံးတဲ့ `div` နဲ့ `span` တွေက အဓိပ္ပာယ်မရှိဘဲ screen reader အတွက် အချက်အလက် ပေးနိုင်စွမ်း မရှိပါဘူး။

**ဥပမာ -**

```html
<nav>
  <ul>
    <li><a href="#home">ပင်မ</a></li>
    <li><a href="#about">အကြောင်း</a></li>
  </ul>
</nav>
<main>
  <h1>မင်္ဂလာပါ</h1>
  <p>ဒါက အဓိက အကြောင်းအရာပါ။</p>
</main>
```

မှတ်ချက် — heading ကိုလည်း level စနစ်တကျ ချဖို့ အရေးကြီးပြီး `h1` မှ `h2` မှ `h3` အစဉ်လိုက် ဖြစ်ဖို့ လိုပါတယ်။

### Alt Text

`alt` attribute က image ရဲ့ အကြောင်းအရာကို screen reader ဖတ်ပေးဖို့ ပါဝင်ပါတယ်။ ပုံပျက်ရင်လည်း ဒီစာသား ပေါ်ပါတယ်။ ပုံရဲ့ အဓိပ္ပာယ်ကို အနီးစပ်ဆုံးဖော်ပြတဲ့ စာသားကို ရှင်းရှင်းလင်းလင်း ရေးပါ — စာလုံးရေ များလွန်းတာမျိုး မဖြစ်စေဘဲ အဓိကအနှစ်သာရကိုသာ ဖော်ပြပါ။

**ဥပမာ -**

```html
<img src="takkatho-logo.png" alt="Takkatho အမှတ်တံဆိပ်">
<img src="charts.png" alt="ဇန်နဝါရီလ တိုးတက်မှုပြ အချက်အလက် ဇယား">
```

မှတ်ချက် — decorative ဖြစ်တဲ့ ပုံတွေမှာ `alt=""` ကို ထားပေးတာက screen reader ကို ပုံကို ကျော်လွှားစေဖို့ ဖြစ်ပါတယ်။

### Form Label

Form input တစ်ခုစီမှာ `<label>` ရှိဖို့ လိုပါတယ်။ `label` ရဲ့ `for` နဲ့ `input` ရဲ့ `id` တူညီအောင်ပေးရင် screen reader က ဘယ် input အတွက် ဘယ် label လဲ သိနိုင်ပြီး textbox ထဲ အလွယ်တကူ ရောက်နိုင်ပါတယ်။

**ဥပမာ -**

```html
<label for="phone">ဖုန်းနံပါတ်</label>
<input type="tel" id="phone" name="phone">
```

မှတ်ချက် — placeholder text ထည့်ထားရုံနဲ့ label ရဲ့ အစားထိုး မဟုတ်ဘဲ label ကတော့ အမြဲ ထည့်ထားသင့်ပါတယ်။

### Contrast (အရောင် ဆန့်ကျင်ဘက်)

Text နဲ့ background အကြား contrast ပြတ်သားမှုက ဖတ်ရလွယ်ကူမှုကို ဆုံးဖြတ်ပါတယ်။ Contrast နည်းလွန်းရင် အရောင်အားနည်းသူတွေနဲ့ မျက်စိမှုန်တဲ့သူတွေ ဖတ်ရခက်ပါတယ်။ ပုံမှန် text အတွက် contrast ratio 4.5:1 တောင် ရှိသင့်ပါတယ်။

**ဥပမာ -**

```html
<p style="color: #333333; background-color: #ffffff;">ဒီစာသားက ဖတ်ရလွယ်ပါတယ်။</p>
```

မှတ်ချက် — မီးခိုးပေါ်မှာ ပြာပြာလေး၊ အဖြူပေါ်မှာ အဝါဖျော့ဖျော့လို ပေါင်းစပ်မှုတွေက contrast နည်းလွန်းလို့ ရှောင်သင့်ပါတယ်။

### Keyboard Navigation

Mouse မသုံးနိုင်တဲ့သူတွေ Tab ခလုတ်နဲ့ page ထဲ သွားလာပါတယ်။ Default HTML element တွေက keyboard နဲ့ အလိုအလျောက် အသုံးပြုလို့ရပေမယ့် အစီအစဉ်ကို ဆိုသလိုဖြစ်အောင် DOM order ကိုလည်း မှန်ကန်စေဖို့ သတိထားရပါတယ်။ Focus ကိုမြင်ရအောင် ရှင်းရှင်းလင်းလင်း outline ကိုလည်း ထားပေးသင့်ပါတယ်။

**ဥပမာ -**

```html
<a href="#content">အဓိက စာသားဆီ ခုန်ရန်</a>
```

မှတ်ချက် — Tab နဲ့ စမ်းသပ်ကြည့်ပြီး focus နေရာကို မြင်ရကြောင်း သေချာစေပါ။ ဒီ pattern က skip link လို့ခေါ်ပြီး navigation ကို ကျော်ပြီး အကြောင်းအရာဆီ သွားနိုင်စေပါတယ်။

### ARIA အခြေခံ

ARIA (Accessible Rich Internet Applications) က HTML မှာ မဖော်ပြနိုင်တဲ့ အဓိပ္ပာယ် ထပ်ထည့်ပေးပါတယ်။ `aria-label` က element အတွက် နာမည်ပေးပြီး `role` က element ရဲ့ တာဝန်ကို သတ်မှတ်ပေးပါတယ်။ Native HTML tag ဖြင့် ဖော်ပြနိုင်ရင် ARIA မလိုပါဘူး — HTML tag ကိုသာဦးစားပေး သုံးပါ။

**ဥပမာ -**

```html
<button aria-label="စာရင်းထဲ ထည့်ရန်">+</button>
<div role="alert">မတွေ့ရှိပါ</div>
```

မှတ်ချက် — button ရဲ့ မျက်နှာပြင်စာသားဖြစ်တဲ့ + ကို aria-label ဖြင့် အဓိပ္ပာယ်ဖော်ထားပြီး screen reader က ဒီအဓိပ္ပာယ်ကို ဖတ်ပေးပါတယ်။
