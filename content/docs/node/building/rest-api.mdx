**REST API** — resources ‌အပေါ် HTTP methods ‌ဖြင့် ‌လုပ်ဆောင်ချက် — ‌စနစ်တကျ design ‌လုပ်‌နည်း။

## Resources ‌နှင့် Methods

| Method | ‌လုပ် | URL |
| --- | --- | --- |
| `GET` | ‌ဖတ် | `/users`, `/users/:id` |
| `POST` | ‌ဖန် | `/users` |
| `PUT` / `PATCH` | ‌ပြင် | `/users/:id` |
| `DELETE` | ‌ဖျက် | `/users/:id` |

## Design rules
- Nouns (actions ‌မဟုတ်) — `/users`, `/orders`
- Plural — `/users` not `/user`
- Nested — `/users/:id/orders`
- Status codes ‌အ‌မှန်သုံး

## Status codes
| Code | ‌အဓိပ္ပာယ် |
| --- | --- |
| 200 / 201 | OK / Created |
| 204 | No content |
| 400 / 404 | Bad request / Not found |
| 401 / 403 | Unauthorized / Forbidden |
| 500 | Server error |

## Example

```js
// GET /api/users?page=2
app.get("/api/users", (req, res) => {
  const page = Number(req.query.page) || 1;
  res.json({ page, data: users.slice((page - 1) * 10, page * 10) });
});

app.post("/api/users", (req, res) => {
  const { name } = req.body ?? {};
  if (!name) return res.status(400).json({ error: "name required" });
  res.status(201).json({ id: 99, name });
});
```

## Versioning

```bash
/api/v1/users
/api/v2/users
```

## ‌အဓိက အချက်များ
- Nouns + plural resources
- Methods ↔ CRUD
- Correct status codes
- Versioning
